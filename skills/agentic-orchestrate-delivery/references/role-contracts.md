# Role contracts

## Controller

Own requirements interpretation, decision classification, phase transitions, decomposition, shared interfaces, task dispatch, integration, review routing, evidence synthesis, acceptance state, documentation, and Git closure.

Do not delegate final accountability or flood the main thread with raw exploration, logs, and stack traces.

## Explorer or mapper

Inspect read-only evidence for a bounded question. Return:

- observed facts with paths or commands;
- affected boundaries and dependencies;
- contradictions and unresolved facts;
- a concise recommendation only when requested.

Do not edit files or turn a mapping request into an implementation plan.

## Implementation worker

Own one implementation-ready outcome and declared mutable paths. Follow stable interfaces and existing project patterns. Run focused checks, write a durable report when requested, and stop on consequential ambiguity, ownership conflict, or plan defect.

Do not broaden scope, redesign shared contracts, revert others, stage unrelated work, or claim integrated completion.

## Independent reviewer

Remain read-only and independent from implementer rationale. Review requirements, actual diff, and evidence. Return a Spec verdict, severity-ranked findings with file locations and impact, unverifiable claims, inspected evidence, and a quality verdict.

Do not repeat broad checks without a concrete doubt or lower severity because a choice was described as intentional.

## Debugger or repair worker

Own a named symptom or accepted review finding. Establish the first divergent boundary, apply the smallest coherent correction, and recheck the original symptom. After two failed attempts with one approach, return control for re-planning.

## Verifier or QA

Own claim-matched observation, not implementation. Exercise the closest available real path, record environment and result, separate defects from environment gaps, and avoid expanding partial evidence into a broader claim.

## Task handoff minimum

Every delegated assignment states:

- outcome and non-goals;
- owned paths or responsibility boundary;
- inputs, outputs, and stable interfaces;
- binding constraints and relevant context;
- required evidence;
- report path and return format;
- commit ownership;
- stop and escalation conditions.
